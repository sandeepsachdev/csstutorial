CSS for Mobile Devices

Phones are not just narrow desktops. They have touch input, notches, on-screen keyboards, retina displays, and limited bandwidth. This page covers the CSS techniques that matter most, with the exact rules used.

On this page: 1. Viewport meta 2. Mobile-first 3. Touch targets 4. Safe areas 5. Fluid type 6. Show/hide 7. Hover on touch 8. Stack columns 9. Mobile forms 10. Bottom nav bar 11. Slide-in drawer 12. Sticky mobile CTA 13. Horizontal card scroll 14. Test checklist

1. The viewport meta tag (HTML, not CSS — but essential)

<meta name="viewport"
      content="width=device-width, initial-scale=1.0, viewport-fit=cover">

Without this the browser will render at 980px and scale down, ruining all your carefully designed mobile styles. Every page in this app sets it.

2. Mobile-first CSS

Write the phone styles as the default, then add complexity at larger sizes.

/* base = phone (no media query needed) */
.card { padding: 1rem; font-size: 1rem; }

/* enhance for tablets+ */
@media (min-width: 768px) {
  .card { padding: 2rem; font-size: 1.125rem; }
}

3. Touch targets — aim for 44×44px minimum

Apple's HIG and the WCAG both recommend a tappable area of at least 44×44 CSS pixels. Compare these two buttons:

.touch.bad {
  width: 24px; height: 24px;   /* too small, hard to hit */
  padding: 0;
}

.touch.good {
  min-width: 44px;
  min-height: 44px;
  padding: 0.5rem 1rem;         /* extra tap area beyond the visible size */
}

/* Enlarge tap targets invisibly with ::before */
.icon-btn { position: relative; }
.icon-btn::before {
  content: "";
  position: absolute;
  inset: -8px;                  /* pushes the invisible hit-zone outward */
}

4. Safe-area insets (notches, home indicators)

/* In your <head>: */
<meta name="viewport"
      content="width=device-width, initial-scale=1, viewport-fit=cover">

/* In your CSS: */
.footer {
  padding-bottom: calc(1rem + env(safe-area-inset-bottom));
}
.header {
  padding-top:  calc(0.75rem + env(safe-area-inset-top));
  padding-left: calc(1rem + env(safe-area-inset-left));
  padding-right:calc(1rem + env(safe-area-inset-right));
}

env(safe-area-inset-*) exposes the device's reserved areas so your buttons don't sit under the home indicator or the notch.

5. Fluid typography with clamp()

Resize me to see clamp() at work.

.fluid-heading {
  /* clamp(min, preferred, max)
     - grows/shrinks with the viewport
     - never smaller than 1.25rem
     - never bigger than 2.5rem                                    */
  font-size: clamp(1.25rem, 4vw + 0.5rem, 2.5rem);
}

/* Fluid spacing works the same way */
.section { padding: clamp(1rem, 3vw, 3rem); }

6. Show / hide by viewport

Phone view Tablet/desktop view 
.mobile-only  { display: inline; }
.desktop-only { display: none; }

@media (min-width: 768px) {
  .mobile-only  { display: none; }
  .desktop-only { display: inline; }
}
/* Prefer showing different CONTENT this way; prefer restyling the SAME
   element (with flex-direction, grid, etc.) whenever possible. */

7. Disable hover styles on touch devices

/* Only apply hover effects when the device actually has a hover-capable pointer */
@media (hover: hover) {
  .card:hover { transform: translateY(-2px); }
}

/* Reset the ugly grey iOS tap flash */
a, button { -webkit-tap-highlight-color: rgba(14, 165, 233, 0.2); }

9. Mobile-friendly forms

/* Inputs must be at least 16px or iOS zooms in on focus */
.mform input {
  font-size: 16px;
  padding: 0.75rem;             /* generous tap area          */
  border: 1px solid #cbd5e1;
  border-radius: 8px;
  width: 100%;
}

.mform label { display: flex; flex-direction: column; gap: 0.25rem; }
.mform       { display: flex; flex-direction: column; gap: 1rem;   }

/* Bonus — HTML attributes matter as much as CSS on mobile */
<input type="email"    inputmode="email"    autocomplete="email">
<input type="tel"      inputmode="tel"      autocomplete="tel">
<input type="number"   inputmode="decimal">
<input type="search"   enterkeyhint="search">

11. Slide-in drawer / off-canvas menu

Toggle the checkbox — no JavaScript needed.

HomeProjectsTeamSettings 
.drawer-checkbox { display: none; }

.drawer {
  position: fixed;
  inset: 0 auto 0 0;                /* top:0 bottom:0 left:0 */
  width: min(80vw, 320px);
  background: white;
  padding: 1rem;
  transform: translateX(-100%);     /* start off-screen */
  transition: transform 0.25s ease;
  z-index: 20;
}

.drawer-scrim {
  position: fixed; inset: 0;
  background: rgba(0, 0, 0, 0.4);
  opacity: 0; pointer-events: none;
  transition: opacity 0.25s ease;
  z-index: 10;
}

/* The checkbox drives the state (:checked ~ sibling combinator) */
.drawer-checkbox:checked ~ .drawer       { transform: translateX(0); }
.drawer-checkbox:checked ~ .drawer-scrim { opacity: 1; pointer-events: auto; }

14. Test checklist

  • Open in Chrome DevTools device toolbar at 360×640 (small Android).
  • Verify nothing scrolls horizontally.
  • Verify body text is ≥ 16px (avoids zoom-on-focus on iOS).
  • Tap each button — are they at least 44×44px?
  • Try landscape orientation.
  • Try the OS dark mode.
  • Turn on "Reduce Motion" and confirm animations calm down.
  • Check safe-area padding on an iPhone with a notch (simulator or real device).
