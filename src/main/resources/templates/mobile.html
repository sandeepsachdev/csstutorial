CSS for Mobile Devices

Phones are not just narrow desktops. They have touch input, notches, on-screen keyboards, retina displays, and limited bandwidth. This page covers the CSS techniques that matter most.

1. The viewport meta tag (HTML, not CSS — but essential)

<meta name="viewport"
      content="width=device-width, initial-scale=1.0">

Without this the browser will render at 980px and scale down, ruining all your carefully designed mobile styles. Every page in this app sets it.

2. Mobile-first CSS

Write the phone styles as the default, then add complexity at larger sizes:

/* default = phone */
.card { padding: 1rem; font-size: 1rem; }

/* enhance for tablets+ */
@media (min-width: 768px) {
  .card { padding: 2rem; font-size: 1.125rem; }
}

4. Safe-area insets (notches, home indicators)

/* In your <head>: */
<meta name="viewport"
      content="width=device-width, initial-scale=1, viewport-fit=cover">

/* In your CSS: */
.footer {
  padding-bottom: env(safe-area-inset-bottom);
}

env(safe-area-inset-*) exposes the device's reserved areas so your buttons don't sit under the home indicator.

6. Hide / show by viewport

Two small helpers used everywhere in this tutorial:

.mobile-only  { display: block; }
.desktop-only { display: none; }

@media (min-width: 768px) {
  .mobile-only  { display: none; }
  .desktop-only { display: block; }
}

7. Disable hover styles on touch devices

@media (hover: hover) {
  .card:hover { transform: translateY(-2px); }
}

Only apply hover effects when the device actually has a hover-capable pointer. This avoids "sticky hover" on phones.

9. Smooth scrolling & tap highlight

html { scroll-behavior: smooth; }
a, button { -webkit-tap-highlight-color: transparent; }

10. Test checklist

  • Open in Chrome DevTools device toolbar at 360×640 (small Android).
  • Verify nothing scrolls horizontally.
  • Verify text is at least 16px (avoids zoom-on-focus on iOS).
  • Tap each button with the mouse — are they easy to hit?
  • Try landscape orientation.
  • Try the OS dark mode.
