Media & Container Queries

Media queries apply CSS only when conditions match — the most common being the viewport width. Resize this page or rotate your phone to see the demos react. Container queries do the same thing based on the size of a parent element.

On this page: 1. Anatomy 2. Live badge 3. Breakpoints 4. min vs max-width 5. prefers-* queries 6. Responsive grid 7. Container queries

1. Anatomy of a media query

@media (min-width: 768px) {
  .card { padding: 2rem; }
}

/* Combine conditions with "and", separate alternatives with "," */
@media (min-width: 768px) and (orientation: landscape) { … }
@media (max-width: 480px), (max-height: 400px)         { … }

/* Negate with "not" */
@media not all and (min-width: 768px) { … }

3. Common breakpoints (mobile-first)

/* base = phones (no @media needed — these are the default) */
.card { padding: 1rem; font-size: 1rem; }

@media (min-width: 480px)  { /* large phones */ }
@media (min-width: 768px)  { /* tablets     */ .card { padding: 1.5rem; } }
@media (min-width: 1024px) { /* laptops     */ .card { padding: 2rem;   } }
@media (min-width: 1440px) { /* desktops    */ }

4. min-width vs max-width

  • min-width — "from this width and up". Pairs with mobile-first CSS.
  • max-width — "up to this width". Pairs with desktop-first CSS.

Stick to one. Most teams pick mobile-first because the base styles work everywhere and you only add complexity on bigger screens.

/* Mobile-first (recommended) */
.nav { display: block; }             /* stacked default */
@media (min-width: 768px) {
  .nav { display: flex; }            /* becomes horizontal on tablets+ */
}

/* Desktop-first (the older style) */
.nav { display: flex; }
@media (max-width: 767px) {
  .nav { display: block; }
}

5. User-preference queries

These respect settings the user has already chosen at the OS level. Every page in this app uses them.

/* User prefers dark theme */
@media (prefers-color-scheme: dark) {
  :root { --bg: #0f172a; --fg: #e2e8f0; }
}

/* Reduced motion — respect vestibular disorders */
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: 0.001ms !important;
    transition-duration: 0.001ms !important;
  }
}

/* No hover-capable pointer — likely touch */
@media (hover: none) and (pointer: coarse) {
  .btn:hover { transform: none; }    /* skip sticky hover effects */
}

/* High contrast mode */
@media (prefers-contrast: more) {
  .btn { border: 2px solid currentColor; }
}

/* Orientation */
@media (orientation: landscape) { … }
@media (orientation: portrait)  { … }

7. Container queries — style based on a parent, not the viewport

The same card looks different in a wide slot vs a narrow one. Try resizing the page — each card responds to its own container.

Wide container

Because my container is > 400px, I show the horizontal layout.

Narrow container

My container is under 400px, so I stack.

/* 1. Declare the parent as a query container */
.cq-parent {
  container-type: inline-size;    /* the card queries this element's width */
}

/* 2. Base (small) styles */
.cq-card {
  display: flex;
  flex-direction: column;
  padding: 1rem;
  background: #f1f5f9;
  border-radius: 8px;
}

/* 3. Adjust based on the container's width */
@container (min-width: 400px) {
  .cq-card { flex-direction: row; align-items: center; gap: 1rem; padding: 1.25rem; }
}
